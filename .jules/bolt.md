## 2026-10-31 - [Vanilla JS Formatting Overhead]
**Learning:** Native `Date.prototype.toLocaleDateString` and `Number.prototype.toLocaleString` implicitly instantiate `Intl` formatters every single time they are called. In large loops or tables (like `renderExpenses` and `updateCurrency`), this creates substantial garbage collection and CPU overhead. Additionally, instantiating `Date` objects just to sort ISO 8601 string dates is redundant because standard lexicographical string comparison is accurate and nearly two orders of magnitude faster.
**Action:** Cache explicit `Intl.DateTimeFormat` and `Intl.NumberFormat` instances at the top level and reuse their `.format()` methods. Always sort ISO 8601 date strings (`YYYY-MM-DD`) using standard string operators (`<`, `>`) instead of converting them to `Date` objects when chronological order is identical to alphabetical order.
